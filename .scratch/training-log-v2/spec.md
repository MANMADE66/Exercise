## Problem Statement

后端已经齐了：14 个端点全部落地，契约机器生成进 `api-types.ts`，193 例 pytest 全绿。但训练者登录之后看到的仍是骨架：

- 月历页只有一句「骨架占位」和当前用户名 —— 看不到这个月哪几天练、哪天休息、哪天已经记过、哪天是今天，翻不了月。
- 点不开任何一天 —— 计划条目、实际完成、感受笔记、按计划预填、上下移、删除，全部没有入口。
- 每周该填的体重没有输入框，周体重记录在 UI 上根本不存在。
- 模板页只有一段说明 —— 存不了循环模板，也没法把模板铺到日历上。
- 因此 HLD §12.0 的验收主线（登录→月历→展开→autosave→预填→模板 apply→周体重→登出）跑不了；prod 静态托管与删除旧 `app/` 也一直不敢切。

一句话：**功能语义都在后端活着，但在浏览器里用不到**。用户此刻既不能用 v1 的方式记一天训练，也不能确认 v2 有没有把 v1 的交互平移对。

## Solution

把 v1 的四个界面块按「交互原样平移」（D9）搬成 Vue 组件，接上真实端点，视觉沿用方向 A：

- **月历**：整周网格、月份翻页、休息日标签、今天标记、已记录小圆点、每行右侧周体重输入框。
- **日详情**：点格子就地展开一行，计划列（增/删/上下移、剂量展示）与实际列（失焦即存、按计划预填、计划外新增、删除）并排，下方感受文本域 + 保存。
- **模板**：列表（名称 + 天数）、按起始日铺到日历并提示新建/跳过数、删除模板、新建表单（天数 + 12 个日块）。
- **外壳**：顶栏收纳用户名/导航/登出；方向 A 令牌与月历、详情、模板样式整份迁入。

完成判据：一条完整的手动冒烟主线能从登录走到登出，全程不刷新页面、不出现白屏；`bash scripts/verify.sh` 全绿（本 spec 不动后端契约，生成物应零 diff）。

## User Stories

### 月历

1. 作为训练者，我想登录后直接落在本月月历，这样我不用先找入口就能看到这个月练了些什么。
2. 作为训练者，我想看到整周的网格（周一起始、本月首尾补空），这样每个日期都落在正确的星期列上。
3. 作为训练者，我想点「上个月 / 下个月」翻页，这样我能回看或预排别的月份。
4. 作为训练者，我想每个格子里看到日期数字，这样我能定位具体是哪一天。
5. 作为训练者，我想训练日显示我写过的标题，这样我一眼知道那天练什么部位。
6. 作为训练者，我想休息日固定显示「休息」标签，这样我不用点开就知道那天是休息。
7. 作为训练者，我想已记录的日期带一个小圆点标记，这样我知道哪几天已经填过实际完成。
8. 作为训练者，我想今天的格子有「今天」标记且数字加粗，这样我能立刻找到今天。
9. 作为训练者，我想不属于本月的补齐格是空白的、点了没反应，这样我不会误以为那天有记录。
10. 作为训练者，我想被展开的那一格高亮，这样我知道下面那一行详情属于哪一天。
11. 作为训练者，我想月历加载失败时看到一句人话错误而不是白屏，这样我知道是后端没起来还是我在网外。
12. 作为训练者，我想翻月后仍停在我刚翻到的那个月（服务端回退生效的月份为准），这样标题和网格不会对不上。

### 日详情

13. 作为训练者，我想点某一天就在那一行下面就地展开当天详情，这样我不离开月历就能看当天内容。
14. 作为训练者，我想再点同一格收起详情，这样我不必找关闭按钮。
15. 作为训练者，我想点另一天时前一天的详情自动收起，这样屏幕上永远只有一天的详情。
16. 作为训练者，我想切月时自动收起详情，这样我不会看到不属于当前月份的展开内容。
17. 作为训练者，我想详情标题显示年月日和我写过的当天标题，这样我确认自己点对了日子。
18. 作为训练者，我想休息日在详情里也标明「休息日」，这样上下文一致。
19. 作为训练者，我想计划条目按我排的顺序列出动作名和剂量（重量 kg · 组数 · 次数），这样我一眼看到该练多少。
20. 作为训练者，我想没填的重量/组数/次数在剂量里直接跳过、不显示「None」，这样界面干净。
21. 作为训练者，我想当天没有计划条目时看到「还没安排」，这样我知道不是加载失败。
22. 作为训练者，我想给计划条目点上移/下移，这样我能调整顺序而不用删了重加。
23. 作为训练者，我想在第一个上移、最后一个下移时按钮不报错（静默成功），这样我不必先判断边界。
24. 作为训练者，我想删掉一条计划条目，这样排错了能纠正。
25. 作为训练者，我想删掉计划条目后已记录的实际条目仍然保留（只断开关联），这样我删计划不会抹掉我练过的事实。
26. 作为训练者，我想用一行小表单添加计划条目（动作 / 重量 / 组数 / 次数），这样我能随手排一条。
27. 作为训练者，我想重量能写「60」「60kg」「62,5」，这样我不用记格式。
28. 作为训练者，我想添加、移动、删除后详情立刻显示最新状态（不刷新页面），这样操作有即时反馈。
29. 作为训练者，我想实际条目每行的重量/组数/次数/备注输入框在失焦时就保存，这样我边练边记不用找保存键。
30. 作为训练者，我想清空某个字段（清掉「备注」）也能保存，这样我能删掉写错的内容。
31. 作为训练者，我想一次只改一个字段时其它字段不受影响，这样我改重量不会把备注冲掉。
32. 作为训练者，我想「按计划预填」一键把当天计划复制成实际条目，这样练完不用逐条手打。
33. 作为训练者，我想预填可以重复点而不产生重复行，这样我不怕多点一次。
34. 作为训练者，我想当天没有计划条目时不显示预填按钮，这样我不会点到无效操作。
35. 作为训练者，我想新增计划外条目（动作 / 重量 / 组数 / 次数），这样临时加的动作也能记。
36. 作为训练者，我想删除实际条目，这样记错的一行能去掉。
37. 作为训练者，我想在详情底部写感受并点保存，这样我把当天状态留在那天。
38. 作为训练者，我想把感受清空再保存也能生效（不再是删不掉的内容），这样我能改写或抹掉。
39. 作为训练者，我想保存感受后详情不收起，这样我能接着改别的。
40. 作为训练者，我想任何一次写操作失败都在详情顶部看到一条中文错误，这样我知道刚才那下没生效。
41. 作为训练者，我想别处已经删掉的条目（另一台设备/另一个标签页）在我操作时提示「已经不存在了」并自动刷新当天内容，这样界面不会停在脏状态。
42. 作为训练者，我想 token 过期时被直接送回登录页，这样我不会在失效状态下一直点。
43. 作为训练者，我想请求进行中触发按钮暂时禁用，这样我不会连点造成重复写入。
44. 作为训练者，我想快速切到另一天时，前一天的慢响应不会把内容画到新的一天上，这样我看的永远是当前这天的数据。

### 周体重

45. 作为训练者，我想月历每一行右侧有个体重输入框（占位 kg），这样我按周记体重而不必去别的页面。
46. 作为训练者，我想本周已有体重时输入框预填出来，这样我知道上周填了什么。
47. 作为训练者，我想体重失焦即保存，这样不用点按钮。
48. 作为训练者，我想体重写错（空、负数、乱码）时不落库、输入框还原成上次保存值、并在这一行提示，这样我的数据不会被脏值覆盖。
49. 作为训练者，我想体重保存成功后这一行立刻显示新值，且不需要刷新整页。
50. 作为训练者，我想保存体重不会顺手清掉我这周原本填过的体脂率和备注，这样我没见过的字段也不会被我弄丢。

### 模板

51. 作为训练者，我想在模板页看到所有模板的名称和天数，这样我能认出哪套是哪套。
52. 作为训练者，我想每个模板旁有起始日期（默认今天）和「铺到日历」，这样我能一键排到未来几天。
53. 作为训练者，我想铺排后看到「新建 N 天，跳过 M 天」以及被跳过的具体日期，这样我知道哪几天因为我已排过而没动。
54. 作为训练者，我想铺排绝不覆盖我已经写好的日期，这样我不用怕丢数据。
55. 作为训练者，我想新建模板时填名称、天数（默认 8）、以及每天的部位标题 + 是否休息 + 动作（一行一个），这样我把循环存下来复用。
56. 作为训练者，我想天数填超了（>12）或填错了也能存下来（截断/回退），这样我不必猜校验规则。
57. 作为训练者，我想删除不要的模板，这样列表不会越堆越长。
58. 作为训练者，我想删除模板前被确认一次，因为模板连带的天和条目一起没了、撤不回来。
59. 作为训练者，我想模板列表为空时有提示，这样我知道是还没建而不是没加载出来。

### 外壳与视觉

60. 作为训练者，我想顶栏显示我的用户名以及「月历 / 模板」导航，这样我知道自己是谁、能换页。
61. 作为训练者，我想当前所在页面在导航里高亮，这样我不会迷路。
62. 作为训练者，我想点登出后清掉会话回到登录页，这样共用设备时我能干净退出。
63. 作为训练者，我想界面沿用 v1 那套浅色极简方向（近白底、少边框、靠留白和字重分层），这样 v2 看起来还是我熟悉的那本记录本。
64. 作为训练者，我想在 1024 宽的窗口里各列不挤在一起，这样我在笔记本上也能用。
65. 作为训练者，我想所有输入框都有可读的标签（供读屏与自动填充），这样我不必靠占位符猜字段。

## Implementation Decisions

**契约消费**

1. 出海口模块（`api.ts`）新增 14 个端点的包装：月历读、日聚合读、计划条目增/删/移、实际条目预填/增/改/删、感受保存、模板列表/新建/删除/铺排、周体重 upsert。全部返回类型直接取生成物（`components["schemas"][...]`），不新写任何形状；若某处必须 `as` 断言才通得过 `vue-tsc`，视为契约缺口，停下切后端票，不在前端绕。
2. `api.ts` 既有的 token 注入、401 清会话跳登录、错误体归一（字符串 detail / 422 数组 / 网络失败 status 0）保持不变，业务组件只消费 `ApiError.status` 与消息，不自己判断 401。

**状态归属（不引入 Pinia，HLD §2 维持）**

3. 月历聚合的唯一持有者是 `CalendarView`；日聚合的唯一持有者是 `DayDetail`（按 `date` prop 挂载即拉取，日期变化重拉）；模板列表归 `TemplatesView`；周体重某一行的 metric 归 `WeekMetric` 自己。
4. 所有日级写操作的响应体即新的日聚合，**整体替换**本地快照，不发二次 GET、不做乐观更新（D7、SRS FR-6.5）。
5. 月历不随日级写操作刷新（v1 亦然）：预填/新增实际条目后，月历的「已记」圆点要等下次进入月历才更新。这是与 v1 一致的已知行为，本轮不引入跨视图失效机制。
6. 月历每次进入都重新请求，模板页不需要通知月历失效；铺排后停在模板页并显示提示（v1 同）。

**月历与展开行**

7. 组件划分沿用 HLD §4.1 的点名：`TopBar`、`MonthGrid`、`WeekMetric`、`DayDetail`；App 收敛为外壳（顶栏 + `RouterView`），登出逻辑下沉 `TopBar`。
8. `MonthGrid` 只负责表结构：表头（一~日 + 周体重列）、按周渲染行、格子状态类（休息 / 今天 / 已选 / 已记录）。展开行由 `MonthGrid` 统一渲染为「跨 8 列的整行」，内容通过作用域插槽交给视图填 —— 这样 `colspan` 只有一处、`<tbody>` 结构永远合法，且日详情状态不会漏进月历组件。
9. `MonthGrid` 的接口：props = 周数组、当前选中日期、今天日期、已记录日期集合；emit = 选中某日期。视图把 `logged_dates` 转成 `Set` 再传（渲染循环里做 `includes` 是 O(n²)）。
10. 已记录标记与「当天有 PlanDay」是两条独立信息（`CONTEXT.md` 已定义）：圆点只看实际条目存在与否，格子标签只看 kind/title。补齐位（`null` 格子）既不可点也不画圆点。
11. 契约不带 `today`，前端用本地日期算；只影响视觉标记。

**日详情**

12. 展开/收起：点格子展开 → 点同一格收起 → 点另一天先收起再展开；切月时清空展开态；不加关闭按钮、不做 Esc（v1 无）。
13. `DayDetail` 的接口：props = 日期；无 emit（收起由月历格子点击驱动）。内部持有聚合、加载态、错误消息、每类操作的进行中标记。
14. 计划列的剂量展示与周体重的重量文本由纯函数提供：重量按「无多余小数、去尾零」输出，剂量按「重量 kg · N 组 · 次数」用 `·` 拼接、空值跳过。这是 v1 Jinja 过滤器语义的等价物。
15. 实际条目的 autosave **逐字段**：某个输入框失焦只提交该字段（PATCH 契约的「缺省不动」正好支持），空串表示置空。不整行提交 —— 否则用户在两秒内先后失焦两个字段时，第二个请求会带着第一个字段的旧快照把它写回去（丢失更新）。
16. 感受用显式「保存」按钮（v1 就是按钮，不是 autosave）；空文本可保存；保存后详情不收起。
17. 「按计划预填」按钮仅在当天有计划条目时出现（v1 同）。
18. 请求期间禁用触发它的控件（含正在保存的行），不做全局遮罩；删掉/移完/加完后以响应聚合为准重绘。
19. 错误显示在详情顶部一处（不逐行弹）；404（资源已被别处删除）提示「这条已经不存在了」并重拉当日聚合；其它 4xx 只提示不重拉。
20. 竞态守卫：每个详情实例记住自己最后一次请求的日期；响应到达时若日期已变（用户切了天/切了月）直接丢弃。写操作按「最后完成者生效」替换聚合。

**周体重**

21. 周体重输入框放在每行右侧的周体重列；周起点取自行数据（契约保证非空）。
22. 保存成功用返回的 metric 就地替换该行，不重拉月历（v1 是整页重载，v2 不需要）。
23. **整体替换陷阱**：`PUT /metrics/{week_start}` 是整体替换，只传 `weight` 会把该周已有的 `body_fat_pct` 与 `note` 静默写成 NULL。前端保存时必须把当前行 metric 里的体脂率与备注原值一并回传。这两个字段本轮仍不加输入控件（v1 也没有），但绝不许被前端误删。
24. 体重非法（422）时输入框还原成上次保存值，并在该行内提示（v1 是重载后顶部 flash；v2 不重载，用「还原 + 行内」，语义等价于 SRS FR-10.2「前端在周体重列提示」）。

**模板**

25. 模板列表每项：名称 · N 天 + 起始日期输入（默认今天）+「铺到日历」+「删除」。
26. 新建表单固定渲染 12 个日块（v1 的 `max_days`），天数输入默认 `"8"`，只决定服务端取前几个日块；每块 = 部位标题 + 休息勾选 + 动作 textarea（一行一个）。名称与天数按**原始文本**提交（契约收文本，服务端负责回退 8 / 截断 12 / 空名补「未命名循环」）。
27. 新建成功后重新拉 `GET /templates`（不在本地拼接，避免与服务端排序不一致）。
28. 铺排结果提示：计数 + 跳过日期列表（契约专门回传 `skipped_dates`）；不自动跳转月历。
29. 删除模板前用一次浏览器确认框 —— 这是 FR-9.4 新开放的能力（v1 无入口）、级联删天与条目且不可撤销，也是本轮唯一新增的交互。删除后重新拉列表。
30. 模板页错误（400 起始日期非法、404 模板已不存在、网络失败）显示在页面顶部。

**视觉**

31. 以 v1 方向 A 的样式表为基座整份迁入：令牌组（`--bg/--surface/--text/--muted/--hairline/--accent/--accent-soft/--danger/--radius/--radius-sm/--gap/--font/--mono`）+ 月历 / 日详情 / 表单 / 模板类名，一个都不改名；骨架期新增的登录页与状态点样式追加在尾部。令牌组的语义映射以 `docs/visual-drafts/README.md` 为准，不重做视觉。
32. 目标宽度 ≥1024（NFR-4），不做移动端适配；所有输入沿用 v1 的 `aria-label`，按钮用真实 `button`。

## Testing Decisions

33. **什么算好测试（本项目口径）**：只断言外部行为 —— 发出的 HTTP 请求与收到的响应、以及界面最终状态；不断言组件内部私有状态、不 mock 组件、不 snapshot DOM。前端没有测试运行器（D10 锁定），所以本轮的「测试」是编译期契约 + 一条手动冒烟主线。
34. **缝 1（契约缝，唯一的机器缝，已存在）**：出海口模块 + 生成的 `api-types.ts`。14 个包装的入参/返回值全部来自生成类型；`vue-tsc` strict（含 `noUncheckedIndexedAccess`、`exactOptionalPropertyTypes`）会把可空字段、可选字段的漏判直接变成编译错误。这是本轮最强的一道关，也是唯一能拦「手写形状」的关。
35. **缝 2（运行时缝，已存在）**：后端 14 个端点 + 193 例 pytest。前端不写 mock / fixture；前端联调中暴露的后端语义问题补后端测试，不在前端加替身。
36. **缝 3（编译缝）**：`vue-tsc --noEmit` + `vite build` 必须过；`oxlint --deny-warnings` + `oxfmt --check` 保持现状。
37. **缝 4（验收缝，本轮新增的文档产物）**：HLD §12.0 的冒烟主线逐条落成清单，写进本轮第一张票的验收段：登录 → 月历（翻月 / 今天 / 休息日 / 已记圆点）→ 展开（添加计划 / 上移下移 / 删除 / 预填幂等 / 四字段 autosave / 计划外新增 / 删除实际 / 感受保存与清空）→ 模板（新建 / 铺排跳过 / 删除）→ 周体重（非法还原 + 合法保存）→ 登出 → token 过期回登录。冒烟用两个账号跑一遍隔离观感（A 的月历里看不到 B 的任何东西）。
38. **建议中的新缝（本轮不加，需人裁定）**：把纯度最高的逻辑（重量文本、剂量拼接、今天日期、月偏移、从 ISO 取月份）收进一个无 DOM 依赖的纯函数模块，为将来测试预留落点；但**现在不引入任何测试运行器** —— 那需要新依赖、要进 HLD §12.1 锁版清单、要改 `verify.sh`，且与 D10「前端无自动化测试」直接冲突。若要加，应当作为独立决策票先改决策，不在本轮偷偷加。
39. 前端 bug 修完不回填前端回归测试（D10）；只有后端语义被动到时才补 pytest。

## Out of Scope

- **prod 静态托管（D11）与删除旧 `app/`（含 `tests/`、`run.py`）**：仍等本轮冒烟通过后另切（map 的「Not yet specified」）。
- **UI 重设计**：视觉方向 B/C、布局改版、移动端适配（SRS §1.2、NFR-4）。
- **体脂率与周备注的输入控件**：端点已有、v1 无 UI；本轮只保证保存体重时不把它们清空。
- **前端自动化测试框架**（vitest / jsdom / Stryker 等）：D10 锁定。
- **新增后端端点或契约字段**：本 spec 只消费既有契约；发现缺口停下切后端票，不在前端手写形状。
- **README 双模式改写**、旧数据迁移（D8）、动作库管理界面（v1 也没有）。
