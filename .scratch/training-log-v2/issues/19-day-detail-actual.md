- [ ] `bash scripts/verify.sh` 全绿、生成物零 diff

## Notes

- **逐字段提交（spec 决策 15）**：不要整行提交。整行快照在「两个字段先后失焦」时会把先改的那个字段写回旧值——契约的三态语义（缺省 = 不动）正是为逐字段准备的。
- 感受用显式「保存」按钮（v1 就是按钮，不是 autosave）；空文本可保存，与「不保存」是两回事。
- 「预填」与「计划外新增」是两种语义：前者当天没有计划日时静默无事（不建日），后者写条目会隐式建日。两条各钉一个验收例。
- 同日写操作串行、最后完成者生效；不要引入乐观更新。

### 做了什么

`DayDetail.vue` 长出第二列与感受区：

- **逐字段 autosave**：每行实际条目的重量/组数/次数/备注各持 `{text, saved, pending}` 草稿；失焦时 `text === saved` 不发请求，否则只 PATCH 该字段（契约三态「缺省不动」正好兜住）；空串 = 置空。成功后回显服务端规范文本（`60kg` → `60`，v1 同）；失败回退 `saved` 基准，下次失焦可重试。
- **草稿同步规则**：聚合替换时新行补草稿、删掉的行丢草稿，**在途 PATCH 字段与正在聚焦的字段不回灌**（`editingKey` 跟踪焦点），两秒内先后失焦两个字段两个改动都保住（AC 核心场景）。
- **预填**：按钮仅在有计划条目时渲染（决策 17）；自带操作锁；服务端幂等，重复点不产生重复行。
- **计划外新增**：四字段原始文本提交，成功清表单；空动作名 422 → 顶部错误。
- **删除**：行级锁（`Set<itemId>`）；成功聚合替换、草稿随行消失。
- **感受**：文本域 + 显式保存按钮（v1 同），空串可保存；保存后详情不收起；写感受期间聚合替换不回灌文本域（`noteEditing`），保存成功回显 trim 后的文本。

### 关键裁定

1. **统一 `execute()`**：等响应 → 整体替换聚合；404 → 先 `refresh()` 成功后才补「这条已经不存在了」。顺带修掉票 18 的潜伏 bug：旧 `runPlanOp` 先设错误再 `refresh()`，而 `refresh()` 开头清错误，提示会被立即抹掉（18 的 404 路径需另一会话配合才触发，本票重构时一并改正，`refresh` 改为成功才清错误并返回布尔）。
2. 锁的粒度：计划列一把锁、预填/新增/感受各一把、字段 PATCH 按字段锁、删除按行锁 —— 决策 18「禁用触发控件，不做全局遮罩」。
3. `body[field] = text` 构造单字段 PATCH（`ActualItemUpdate` 全可选），不手写形状、无 `as`。
4. oxlint 抓掉一处 `[...map.keys()]`：Map 迭代器实时，边遍历边删安全，去掉多余展开。
