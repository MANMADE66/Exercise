## What to build

详情里的第二个列：实际完成。每行是动作名 + 重量/组数/次数/备注四个输入框，失焦即保存、可删行；「按计划预填」把当天计划复制成实际条目且可重复点；「计划外新增」表单用于临时加动作。详情底部是感受文本域 + 保存按钮。

## Acceptance criteria

- [ ] 任一字段失焦只提交该字段；两秒内先后失焦两个字段，两个改动都保住（不互相覆盖）
- [ ] 清空某个字段再失焦能保存（置空生效）
- [ ] 「按计划预填」仅在当天有计划条目时出现；重复点不产生重复行
- [ ] 计划外新增（动作 / 重量 / 组数 / 次数）后立刻出现在末尾；空动作名被拒并提示
- [ ] 删除实际条目后该行消失，聚合随之刷新
- [ ] 感受可保存、可清空；保存后详情不收起
- [ ] 写操作失败在详情顶部提示一处；404 提示「这条已经不存在了」并重拉当天
- [ ] 请求期间触发控件禁用，不产生重复写入
- [ ] `bash scripts/verify.sh` 全绿、生成物零 diff

## Notes

- **逐字段提交（spec 决策 15）**：不要整行提交。整行快照在「两个字段先后失焦」时会把先改的那个字段写回旧值——契约的三态语义（缺省 = 不动）正是为逐字段准备的。
- 感受用显式「保存」按钮（v1 就是按钮，不是 autosave）；空文本可保存，与「不保存」是两回事。
- 「预填」与「计划外新增」是两种语义：前者当天没有计划日时静默无事（不建日），后者写条目会隐式建日。两条各钉一个验收例。
- 同日写操作串行、最后完成者生效；不要引入乐观更新。
